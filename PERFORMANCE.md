## Изменения

- HTML секций и карточек услуг формируется плагином в `vite.config.js` при сборке и в dev-сервере. Браузер получает контент до исполнения JavaScript. Карточки услуг сразу занимают своё место, предотвращая сдвиг следующих секций.
- Баннеры и фотографии врачей используют WebP. Фотографии уменьшены до 280 px для карточек размером до 140 CSS px; мобильные баннеры — до 360 px для отображения в 180 CSS px. Оригиналы сохранены.
- Первый баннер предзагружается с учётом ширины экрана и получает высокий приоритет. Другие изображения слайдера загружаются при переключении или начале жеста. Начальная позиция устанавливается без анимации.
- Шрифты содержат латиницу, кириллицу, пунктуацию и символы. Основной шрифт предзагружается, `font-display: swap` сохранён.
- Nginx сжимает HTML/CSS/JS/SVG через gzip. Файлы Vite с хешем кешируются на год, ресурсы с постоянными именами — на сутки. HTML перепроверяется при каждом посещении; отсутствующие ресурсы возвращают 404.

## Обновление изображений и шрифтов

Готовые WebP и WOFF2 хранятся в репозитории. Обычная сборка не требует Python.
После замены исходных PNG или шрифтов:

```sh
python -m pip install -r scripts/requirements-assets.txt
python scripts/optimize-assets.py
```

При замене первого баннера обновляйте также ссылки `preload` в `index.html`.
При изменении ресурсов с постоянными именами учитывайте кеш до 24 часов; для немедленного обновления используйте новое имя файла.

## Проверка и публикация

```sh
docker compose build frontend
docker compose up -d --no-deps frontend
docker compose exec frontend nginx -t
```

Используйте compose-файл, соответствующий окружению. Эти команды применяют изменения там, где запущены; локальная сборка не обновляет `navident.ru`.

Проверьте мобильное меню, переключение и свайпы баннеров, открытие форм записи, услуг и врачей. У HTML должен быть `Cache-Control: no-cache`, у сжатого ответа — `Content-Encoding: gzip`, у JS/CSS с хешем — `max-age=31536000, immutable`.

После публикации повторите PageSpeed Insights для мобильных устройств. Локальный Lighthouse полезен для сравнения в одинаковых условиях, но его результат не равен замеру публичного сервера.
